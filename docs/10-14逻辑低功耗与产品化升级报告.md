# 10-14 逻辑优化、低功耗与产品化升级报告

> 工程：安路 EG4S20BG256 / HX4S20C，多场景音视频信息终端  
> 本轮位流：`artifacts/pic_sdram_audio_showcase_osd_lp_1014.bit`  
> 优化原则：功能与像素结果不变、时序通过才交付、先做时钟使能/数据门控，不直接门控时钟树。

## 1. 结论

当前工程已经不是“官方例程换素材”，而是一个可独立运行的 **多场景确定性智能信息发布终端**：同一套 TF 卡、SDRAM、HDMI 音视频底座，根据拨码切换迎新、会议、抢答、应急四种业务。作品最有竞争力的不是功能数量，而是三条能够给评委验证的技术主线：

1. **确定性显示**：帧边界提交、首帧有效门控、坏图跳过、场景切换压黑，避免旧帧、半帧和随机残留。
2. **场景化交互**：迎新分辨率常显与音乐降级，会议状态 OSD，抢答动态排名，应急方向箭头，而不是单纯播放图片。
3. **可量化工程优化**：资源、时序、仿真和低功耗活动范围都有前后数据，不把“低功耗”停留在口号。

赛题基础四项与现有扩展功能保持不变。本轮只优化音频可视化内部：最终建立余量 `+0.051 ns`、保持余量 `+0.020 ns`，均为正，生成可烧录位流。

## 3. 当前架构与瓶颈

### 3.1 数据通路

`TF/FAT32/BMP/WAV（100 MHz 域） → 图片缩放与写帧 → SDRAM（125 MHz） → 视频读帧（25 MHz） → 画质/转场/OSD/音频可视化 → HDMI`

控制层独立承担场景、按键、轮播、抢答、会议与应急事件；跨时钟域继续使用原有 FIFO/同步结构。这样的分层使应用功能可以演进，而不破坏已经稳定的 SDRAM 与 HDMI 底座。

### 3.2 资源与效率瓶颈

| 瓶颈 | 证据 | 影响 |
|---|---|---|
| Slice 已接近器件上限 | 最终 8868 slices，90.49% | 大规模新增 FFT、双 HDMI 或复杂字库风险很高 |
| LUT 较高 | 16498/19600，84.17% | 新功能必须复用比较器、坐标译码和 BRAM |
| 视频像素链组合逻辑密集 | `display_adjust` 1892 LE，且坐标/像素每拍变化 | 动态功耗与布线压力的主要可优化区域 |
| 图片缩放与 FAT32 路径较重 | `bmp_scale` 922 LE；关键建立路径位于 FAT32 100 MHz 域 | 激进重构容易破坏读取稳定性和时序 |
| SDRAM/HDMI 常开 | 为持续输出视频所必需 | 不能为了低功耗直接停钟或停刷新 |
| 功耗尚无实测电流数据 | 当前只有活动率代理和资源数据 | 报告中不能虚构 mW 降幅，必须补板级测量 |

## 4. 本轮已经落地的优化

### 4.1 音频可视化 BRAM 读口窗口门控

原实现只要视频时钟运行，横坐标乘 5、柱号译码、环形读地址与 BRAM 读口就整帧活动。本轮增加 `viz_rd_en`，只在 `DE=1` 且 `y=362..437` 的 76 行可视化区域活动：

- 相对 480 行有效画面，关闭了 404 行，即有效区读活动减少 **84.2%**；
- 水平/垂直消隐期也全部关闭 BRAM 读使能；
- 窗口外固定坐标操作数，阻断乘加、地址和高度减法器的无意义翻转；
- 没有用 `show` 直接关 BRAM，避免声音在一帧中途出现时读到陈旧首列。

这是 **时钟使能/数据隔离**，不是危险的组合逻辑门控时钟，符合 FPGA 低功耗设计习惯。

### 4.2 50 位历史移位窗压缩为 6 位寿命计数器

“最近 50 根柱里是否存在非零柱”原来用 50 位移位寄存器与 50 位归约树。本轮改为：非零柱写入时装载 50，零柱写入时递减至 0。

- 与原历史窗口逐拍等价；
- 状态寄存器从 50 位降到 6 位，理论净省 **44 FF**；
- 专项仿真将新实现与原 50 位参考模型逐拍比较，`500/500` 通过；
- TD 门级统计中的寄存器也实际减少 44 个，证明优化没有被报告包装放大。

### 4.3 前几轮已经保留的等价优化

- 视频消隐期冻结无效 RGB 数据，减少像素链无意义翻转；
- 音频静音段冻结 DDS 相位，但保持 48 kHz 输出节拍和 FIFO 通路；
- 删除被全屏排名页遮盖的旧比分绘制链；
- 4 队排名由 12 次比较降为固定 5 比较器排序网络；
- 固定尺寸除法/取模改为阈值比较与减法；
- 未启用 OSD/箭头时隔离局部坐标总线；
- FAT32 目录项从整项缓存改为字段流式提取，保留协议行为并减少资源。

## 5. TD 6.2 量化结果

比较基线为功能已验证的 `pic_sdram_audio_showcase_osd_opt_1013.bit`，两者均使用 seed 59。

| 指标 | 展示优化基线 | 10-14 低功耗版 | 变化 |
|---|---:|---:|---:|
| LUT | 16470 | 16498 | +28 |
| REG | 7564 | 7524 | **-40** |
| LE | 17242 | 17203 | **-39** |
| 最终 slices | 8874 | 8868 | **-6** |
| BRAM9K / BRAM32K | 39 / 8 | 39 / 8 | 0 |
| DSP | 14 | 14 | 0 |
| 建立余量 SWNS | +0.107 ns | +0.051 ns | 均通过 |
| 保持余量 HWNS | +0.020 ns | +0.020 ns | 均通过 |
| 门级最大逻辑层级 | 23 | 22 | **-1** |
| 门级宏单元加法器 | 898 | 895 | **-3** |

权衡是 LUT 增加 28 个，用于安全的窗口判定和数据隔离；换来寄存器、LE、slice 和组合深度下降，以及 BRAM/地址链活动范围显著缩小。低功耗价值来自“少翻转”，不能只按 LUT 数判断。未进行板级电流测量前，不宣称具体 mW 或百分比功耗下降。

## 7. 下一阶段优化路线与取舍

| 优先级 | 优化项 | 预期收益 | 难度/风险 | 决策门槛 |
|---|---|---|---|---|
| P0 | 建立板级功耗基线 | 把低功耗从推断变为证据 | 低；需电流表/功率计 | 记录菜单、静音、播放、告警、抢答结束 5 组电流 |
| P0 | 冷启动与异常素材测试矩阵 | 提升可靠性叙事和现场成功率 | 低 | 无卡、坏图、尺寸错误、掉电、反复切场景全部通过 |
| P1 | SD/WAV 空闲状态 CE 化 | 减少 100 MHz 域空闲翻转 | 中；不能破坏仲裁/首扇区 | 专项仿真 + TF 卡长时间播放 |
| P1 | 共享 OSD 字模与坐标译码 | 回收重复比较器和字模逻辑 | 中高；需保证图层优先级 | 至少节省 100 LUT，像素等价 |
| P1 | 修整无效约束与时序报告 | 消除过期路径告警，提升报告可信度 | 中；约束错误会掩盖真实路径 | 只改确认不存在的层次，前后关键路径一致 |
| P2 | 低资源分频能量可视化 | 比时域柱更有算法深度 | 中高；资源紧张 | 采用时分复用 Goertzel/少频带，不做 1024 点全 FFT |
| P2 | 自检与错误台账 OSD | 可展示坏图跳过、卡故障、启动状态 | 中；产品价值高 | 复用现有字模，资源预算小于 150 LUT |
| P3 | 切歌与播放列表 | 完善“媒体终端”产品体验 | 中；涉及 FAT 遍历和 SD 仲裁 | 先保证图片/WAV 不互相饿死 |
| P3 | 马赛克/复古流式滤镜 | 展示效果明显，算法易解释 | 中；可用位移/量化实现 | 独立模式，默认关闭，像素流水不增帧缓存 |
| 暂缓 | 双屏独立显示 | 区分度高但需要第二输出链和更多带宽 | 极高；当前资源与接口不适合 | 除非更换/扩展硬件，不进入主线 |

禁止项：直接组合门控全局时钟、停止 SDRAM 刷新、修改 PLL/加密 HDMI/SDRAM IP、在高利用率下盲目堆完整 FFT。这些动作可能有“创新”外观，却会伤害可靠性和答辩可信度。

## 8. 最值得做深的两条创新主线

### A. 面向无障碍与应急的“音频语义可视化”

不要只说“波形好看”，而要说明它帮助听障用户或嘈杂环境中的用户感知提示音。下一步采用 4～6 个选择频带的 Goertzel/能量估计，利用 48 kHz 音频相对 100 MHz 系统时钟的巨大空闲周期，时分复用少量 DSP；不同告警音映射为颜色和方向提示。这样算法、场景和社会价值是一条闭环。

### B. 可验证的“确定性与自恢复终端”

把已有坏图/不匹配图片处理、首帧压黑、场景原子提交、TF 缺失时板载音乐降级，统一包装成可靠性体系；增加轻量错误台账和启动自检 OSD。评委能在现场拔卡、放坏图、断电重启，系统仍给出可预测结果。这通常比再堆一个炫技滤镜更像产品。

## 9. 对标高水平答辩的展示顺序

1. **先断电启动**：不接电脑，上电自动进入工作态，证明固化和独立运行。
2. **再展示真实异常**：无 TF 卡自动用板载音乐；放入坏图后自动跳过且系统不停机。
3. **展示四场景闭环**：迎新分辨率常显、会议状态、抢答动态彩色排名、应急箭头与告警。
4. **展示技术证据**：同屏给出前后资源表、正时序、专项仿真和电流实测曲线。
5. **最后讲创新主线**：不是“做了很多功能”，而是“一个架构、四个场景、两条做深的技术主线”。

这套路线能对标高水平竞赛作品的表达和工程完整度，但不能用功能数量保证奖项。真正有说服力的是：每次升级都有可复现测试、可量化收益、明确取舍和实板证据。
