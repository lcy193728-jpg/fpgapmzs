# 10-15 缩放行缓存 BRAM 低功耗优化说明

## 优化对象

`bmp_scale` 用三块行缓存保存相邻源图行，为双线性缩放提供 x0/x1 两列采样。原实现的三个同步读口在 100MHz 时钟下每拍执行读取，即使状态机处于以下阶段也持续激活 BRAM：

- 100% 原尺寸旁路；
- 帧间空闲；
- 等待源图行写满；
- 黑边输出；
- 坐标计算和四级插值流水。

这不会改变像素值，但会让 BRAM 地址译码、感放和输出寄存器持续受时钟驱动，不符合前期低功耗方案中的“存储器无请求不访问”原则。

## 实现方法

双线性取样的既有时序为：

1. `O_CX`：装载 x0 地址；
2. `O_R1`：同步读取 x0；
3. `O_R2`：锁存 x0 数据并装载 x1 地址；
4. `O_R3`：同步读取 x1；
5. `O_R4`：锁存 x1 数据。

因此三个行缓存共用局部读使能：

```verilog
assign line_rd_en = (state == O_R1) || (state == O_R3);
```

只在 `line_rd_en=1` 时更新 d0/d1/d2。综合器仍将三块存储器识别为 1024×24bit BRAM，并把条件映射到 BRAM 原生读使能，而不是在 24bit 数据输出后增加多路器。写口仍由 `in_pix` 和 `wr_buf` 独立控制，因此输入接收与读门控互不影响。

## 活动率收益

| 场景/档位 | 行缓存读使能周期/输出帧 | 说明 |
|---|---:|---|
| 100% 原图旁路 | 0 | 输入直接写入 SDRAM 帧通路，不使用插值行缓存读口 |
| 50% | 320×240×2 = 153600 | 仅图像区域每像素读取 x0/x1 |
| 25% | 160×120×2 = 38400 | 黑边阶段完全禁读 |
| 300% | 640×480×2 = 614400 | 即使满屏插值，12 拍左右的像素流程中也仅 2 拍读 BRAM |
| 帧间空闲/等待源行 | 0 | 原实现会持续读同一地址，现由原生 CE 保持 |

这里没有门控全局时钟，只使用 BRAM 自带的端口使能，因此不引入派生时钟、时钟树偏斜或新的跨时钟域问题。

## 验证结果

### 功能仿真

- 八档配置表全部通过；
- 100%：3072 个小画布像素逐点一致；
- 50%：3072 个像素逐点一致；
- 25%：3072 个像素逐点一致；
- 300%：整帧像素数量正确且无死锁；
- 输入有效保持 3 拍：逐点一致；
- 纵向 2×：整帧逐点一致；
- 专项 BRAM 门控：16370 个禁读周期保持检查通过。

原 `tb_bmp_scale` 的输入激励从时钟上升沿改为下降沿，消除了 testbench 与 DUT 在同一仿真时间片竞争的问题；这只修正仿真驱动时序，不进入综合设计。

显示功能回归继续通过：迎新马赛克 12 项、抢答排名、应急箭头、音频可视化 7 项、冷启动首帧、分辨率常显和 `display_adjust` 56 帧全画布测试。
