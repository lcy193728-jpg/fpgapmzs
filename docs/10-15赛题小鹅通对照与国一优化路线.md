# 10-15 赛题、小鹅通资料对照与后续优化路线

## 1. 结论

当前工程已经不是“官方例程加功能”，而是以 HX4S20C 为核心的四场景多媒体信息终端：
迎新、会议、抢答、应急共享 TF/SDRAM/HDMI/音频底座，各场景在帧边界提交状态，具备
坏图跳过、首帧门控、转场隔离和冷启动保护。基础项完整，五类官方扩展均有覆盖，其中
抢答闭环、场景化 OSD、流式马赛克和不同场景的声画联动构成主要区分度。

当前最重要的工程判断是：**瓶颈已经从“功能不够”转为“切片接近上限、扩展深度和
可量化低功耗证据不足”**。后续不应继续堆零散模式，而应围绕两条主线做深：

1. 把“确定性、无撕裂、可恢复”的视频架构讲透并量化；
2. 把“场景互斥复用 + 存储器原生使能 + 活动隔离”的逻辑/低功耗优化做成可复现实验。

## 4. 当前架构与瓶颈

### 4.1 架构分层

1. **介质入口层**：SD 初始化、FAT32、BMP/WAV 数据流、坏文件过滤、SD 仲裁。
2. **存储与提交层**：SDRAM 多 bank 帧缓存、首帧有效门控、场景装载保护、帧边界提交。
3. **像素处理层**：双线性缩放、亮度/对比度、流式马赛克、转场遮罩。
4. **场景合成层**：菜单、迎新、会议、抢答、应急 OSD；未启用场景尽量局部锁零。
5. **音频层**：48kHz 节拍、TF PCM/DDS 选源、事件音效、可视化、HDMI 数据岛。

这符合小鹅通“基础底座稳定、功能在边界外插入”的原则，也保留了 FPGA 的并行、确定性
和低延迟优势。

### 4.2 实际资源瓶颈（TD 6.2，seed 59，当前接收版）

| 指标 | 使用量 | 占用 | 判断 |
|---|---:|---:|---|
| LUT | 16365 / 19600 | 83.49% | 较高，但不是最紧约束 |
| REG | 7613 / 19600 | 38.84% | 仍有空间 |
| 最终 slices | 8822 / 9800 | 90.02% | **首要瓶颈，仅约 978 slice 余量** |
| BRAM9K | 40 / 64 | 62.50% | 可用，但需考虑布局而非只看数量 |
| BRAM32K | 8 / 16 | 50.00% | 尚有空间 |
| DSP | 14 / 29 | 48.28% | 尚有空间，换 LUT 未必划算 |
| PLL | 2 / 4 | 50.00% | 不建议为功能随意增加时钟域 |
| SWNS / HWNS | +0.121ns / +0.020ns | 0 违例 | 余量小，任何共享/CE 都必须重跑物理实现 |

因此不能用“省 DSP 就一定更好”或“加 CE 就一定更省电”的通用结论。本项目的真实目标函数
应按优先级排序为：**0 时序违例 → slices 不增加 → 可见功能等价 → 活动率下降 → LUT/REG**。

### 4.3 功耗瓶颈

- 25/100/125MHz 多时钟域长期运行，视频和 SDRAM 主链不能停。
- 坐标、RGB 和多层 OSD 是高翻转、高扇出网络；逐寄存器加 CE 会引入大量选择器和布线。
- 行缓存/波形缓存等 BRAM 若无原生使能，会产生无效读活动。
- 未选场景若仍计算几何、字模地址或颜色混合，会把无效翻转传到后级。
- 目前只有活动率代理和资源结果，尚无板级电流/功耗数字；报告中不能把“读次数下降”写成
  “整板功耗下降多少瓦”。

## 7. 面向评委的“国一水平”表达

作品不应以“做了多少特效”为主线，而应讲成一个可验证的 FPGA 多媒体终端：

1. **确定性**：像素、音频、场景状态并行处理；所有可见参数帧边界提交。
2. **可靠性**：首帧门控、坏图跳过、装载保护、CDC 同步、有限状态恢复，消除随机串图。
3. **算法深度**：三行缓存双线性缩放、流式马赛克、固定排序网络、场景化 OSD。
4. **低功耗方法**：不破坏时钟树，优先 BRAM 原生使能、静音冻结、窗口门控和场景隔离。
5. **工程闭环**：每项修改经历专项仿真→完整回归→TD 推断→固定 seed 布局→时序/资源门槛→实板。
6. **诚实量化**：区分“活动率下降”“资源下降”和“整板实测功耗下降”，不夸大结果。

最能吸引评委的下一步不是第四种图片滤镜，而是：**一段连续镜头展示断电自启、坏图自动跳过、
无撕裂切场景、动态排名和应急指引；随后用一张表给出优化前后 slice、时序、BRAM 读活动和
板端电流数据。** 这能同时证明创新性、产品性、FPGA 特性和工程成熟度。

## 8. 当前剩余工作（10-15 最新）

1. **维持固定 seed 物理基线**：稳定源码已重建 candidate 并通过 QoR 门禁；
   构建永远只产生 candidate，不覆盖用户已实板验证的稳定 BIT。
2. **完成板级五工况功耗实测**：这是从“低翻转设计”升级为“低功耗证据”的唯一可靠闭环。
3. **继续筛选场景级粗粒度隔离**：仅处理已有低扇出状态机或存储器原生使能；不再给高扇出
   坐标总线逐拍加 CE，不做直接门控时钟。
4. **维护回归基线**：旧 `tb_display_score` 仍按早期抢答分数弹窗设计，需更新为当前全屏动态
   排名的期望；当前实际排名由 `tb_quiz_ranking` 覆盖并通过。
5. **最后再考虑跨场景 OSD 共享**：HUD 几何共享虽功能等价，但物理结果 +133 slices，说明
   共享边界必须更粗、扇出必须更低；任何候选仍需逐项通过固定 seed=59 门禁。

补充筛选结果：顶层 32 位 48kHz 相位累加器替换为 10 位倒计数+分数相位后，
逐拍等价和音频端到端回归全部通过，但固定 seed 最终 LUT +53、REG +30、LE +241，
因工具复制/装箱效应被淘汰并回退。后续不再优先改造这条已满足时序的全局节拍网络。

回退后基线重建恢复为 LUT 16365、REG 7613、LE 17084、slices 8822、
SWNS `+0.121ns`、HWNS `+0.020ns`，QoR 门禁 9/9 通过。同次 candidate SHA-256 为
`8D18E650C5AB7354DF85430B2F108DB72A452594A2F343514A0E9B2BDFBDCBF8`。

时序约束清理也已落地：旧 `u_audio_events/audio_event_cdc` 已不在产品顶层中例化，
相应 bundled payload `set_max_delay` 长期匹配 0 个对象。删除这条空约束后，真实
`sync_ff[0]` CDC 约束保持不变，USR-6001/8012/8159 消失，资源和时序逐项不变。

DDS 正弦 ROM 刷新 CE 候选在 41828 项仿真检查通过后仍被物理实现淘汰：
工具将 3 块 ROM BRAM 变成逻辑，导致 LUT +439、LE +389、slices +201。该 RTL 已回退。
最新同次 candidate SHA-256 为
`46B8D393C62208B5C47BF077A4191CEE2E53937C309623BEB16539EA75B83FF7`。

新增的自动续项筛选又验证了一个重要边界：会议终值比较等价化，以及抢答 27 位秒计数器

9/9 QoR 门禁通过，当前同源 candidate SHA-256 为
`077AAB5C5CBAD83F2ADD1721A29205ED3D541155BF645C5A76E900F1C2966B0A`。

完全恢复基线，却产生 `-0.535ns` 建立违例。两项均按门禁自动回退。后续不再单独改变
该 BRAM 的端口控制，优先转向无需新增 CE 网络的算法级整块删除；若没有同时改善资源、

“直接减少比较/混色算法且不新增 RGB 选择层”或板级功耗量化值得继续投入。
