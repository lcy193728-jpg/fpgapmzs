## 二、赛题评测维度 vs 我的项目（核心差距分析）

官方明确 5 项扩展要求，每项"选择 1-2 项做深做透"即可获区分度。我的完成度：

| 扩展要求 | 我的现状 | 深度 | 差距/深做方向 |
|---|---|---|---|
| **1. 图层叠加与字幕** | OSD 引擎链（menu/welcome/scene/meeting/emergency/viz 六层），汉字字库，会议议程状态机，应急告警 | ⭐⭐⭐⭐⭐ | **已做透**，行业领先 |
| **2. 图片切换与转场** | 淡入淡出已实现（display_adjust stage2），**滑动/Wipe 未做** | ⭐⭐⭐ | 补 **Wipe 滑动转场**（4 种方向）即做透 |
| **3. 图片缩放适配** | 双线性缩放 + 多分辨率（640×480/1024×768/1280×960/320→640）| ⭐⭐⭐⭐ | 已较深，可补**自适应中心裁剪/非等比** |
| **4. 实时调节+信息叠加** | 亮度/对比度/缩放/周期/音量/会议，数码管+OSD 双显示 | ⭐⭐⭐⭐⭐ | **已做透** |
| **5. 音频可视化** | PCM 波形 + 峰值条（audio_viz_overlay）| ⭐⭐⭐ | **缺真正的 FFT 频谱**，这是最大区分度空缺 |

**结论**：字幕(1)和参数调节(4)已做透，转场(2)差 Wipe、可视化(5)差 FFT，是**最有区分度的两个深做方向**。

## 三、逻辑优化程度 —— 还能再优化的点

### 3.1 已做对的（对标小鹅通框架，均达标）

- 四 bank 帧缓存 + underflow 检测（第八讲）✅
- POR + 全部 PLL locked 才放行复位（第六讲规范）✅
- 跨时钟域统一 2FF 同步 + toggle 握手 ✅
- 帧边界提交（frame_start 锁存，防撕裂）✅
- 窄位宽"相加后右移"零扩展防护（C11 坑）✅

### 3.2 还能再做的逻辑优化

1. **P1 operand isolation（收益最大、可做）**
   - 现状：OSD 六层串联，非活动层仍随像素流翻转坐标比较器/字形查表
   - 改法：各层入口 `wire px_x_g = scene_en ? px_x : 11'd0`，内部比较用 `_g`，透传路径仍用真实坐标
   - 收益：显著降低非活动层动态翻转率（TD 无功耗报告，但这是 FPGA 低功耗设计的标准手法，评委一眼能认出）
   - 难度：中（每层都要小心"门控只作用比较副本，透传用真实坐标"）

2. **时钟门控（clock gating / 使能域）**
   - 会议 OSD/应急 OSD 只在对应场景使能时打拍，用 clock enable 而非常开时钟
   - 收益：进一步降动态功耗

3. **冗余逻辑精简**
   - `sim_modules/` 下 `fade_transition_ctrl.v` 等仿真专用模块若已不在主链路，可清理，避免混淆

## 四、低功耗设计 —— 具体措施清单

| 措施 | 收益 | 难度 | 取舍 |
|---|---|---|---|
| **P1 operand isolation** | 中高（降非活动层翻转） | 中 | 每层需仔细信号分离，回归成本 |
| **时钟门控（CE 域）** | 中（省时钟树翻转） | 中 | 会议/应急 OSD 场景化打拍 |
| **数码管降频（已做）** | 低 | 已做 | 无 |
| **扫描/轮询节流** | 低 | 低 | 状态显示类计数器降低翻转 |
| **BRAM 空闲使能门控** | 低 | 低 | 字库读使能已有 rd_en 门控，可再核对 |

**说明**：TD 6.2 无功耗分析报告（无 Power Report），功耗优化只能靠**结构性手段**（operand isolation、clock gating）体现，无法量化验证。建议把 P1 作为"逻辑优化"叙事的一部分落地（而非单独追求功耗数字）。

## 五、拓展功能深做方向（按区分度排序）

### 方向 A：FFT 音频频谱可视化（⭐⭐⭐⭐⭐ 强烈推荐）

- **赛题扩展要求 5 原文点明 FFT/DFT**，我的项目目前只有波形+峰值条，这是最直观的"从有到深"缺口
- 实现：对 PCM 样本做 N 点 FFT（如 256 点），频谱柱叠加到画面
- 资源：256 点 FFT 需约 3~4 个 DSP（蝶形），当前 DSP 14/29 余 15，**完全够**
- 加分点：这是唯一能"一眼看出你做了算法级设计"的扩展（FFT 是 DSP 硬核考点）

### 方向 B：Wipe 滑动转场特效（⭐⭐⭐⭐）

- 淡入淡出已做，补 4 种 Wipe（左→右/上→下/中心扩散）即可称"完整转场子系统"
- 复用小鹅通第十讲 `video_fade_transition.v` 的 4 状态机 + 像素级坐标比较，改动可控
- 资源：纯组合坐标比较，几乎不占额外 LUT/DSP

### 方向 C：缩略图交互选择（⭐⭐⭐⭐）

- 赛题扩展要求虽未单列，但小鹅通第十二/十五讲是重点，是"产品化程度"的直接体现
- 现状：**完全没实现**，是最大的功能空缺
- 实现：2×2 缩略图（复用现有多分辨率缩放引擎）+ 焦点移动 + 快速选择
- 难度：中高（需新增 thumbnail_controller + 坐标映射切换 + 帧边界提交）

### 方向 D：双开发板联动（⭐⭐⭐ 创新性，去年拓展要求）

- 用户提到的"两个开发板"是去年的拓展要求，**创新性和区分度很高**，但需确认今年是否仍适用
- 可能形态：HDMI 输入 + 输出联动（板 A 输出 → 板 B HDMI IN 显示）、或双板级联拼接画面
- 硬件前提：板卡有双 HDMI 接口 + 72 扩展 IO + 千兆以太网
- **建议先确认今年赛题是否认可此方向**，再投入

## 六、推荐执行顺序（先稳定后深做）

1. **P1 operand isolation**（逻辑优化叙事，低风险收益中）——补足"优化方案全部落地"
2. **方向 A：FFT 频谱**（区分度最高，DSP 余量充足）——做深做透音频可视化
3. **方向 B：Wipe 转场**（改动可控，补全转场子系统）——做深做透图片切换
4. **方向 C：缩略图交互**（产品化加分，工作量最大）——视时间而定
5. **方向 D：双板联动**——先确认赛题适用性再投入

> 每项改动后严格走：ModelSim 仿真 → TD 构建（SWNS/HWNS≥0 + 复核 Hold）→ JTAG/SRAM 上板 → 确认后再固化 Flash。
