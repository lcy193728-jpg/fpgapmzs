# TF 卡图片自动轮播 → SDRAM → HDMI 显示（阶段一/二/2a/2b/2c/2d/2e）

基于安路 FPGA 的 HDMI 多媒体显示系统。开发板读取 TF 卡中的 640×480、24bit 非压缩 BMP 图片，写入片内 SDRAM 帧缓存，经 HDMI 接口以 VGA 分辨率实时输出，实现**上电自动多图循环轮播**。

本工程是「校园多功能 FPGA 智能终端」：**阶段一**完成轮播+按键切图；**阶段二**落地四场景主状态机框架（迎新/会议/抢答/应急抢占）+ 按拨码分区重载素材；**阶段 2a** 把自研**汉字 OSD 引擎**串入视频链路——菜单态显示「四场景首页菜单」，应急态叠加顶部红色警示条；**阶段 2b**在迎新区叠加**展示信息 OSD**（顶部欢迎语/报到地点/联系方式/滚动流程字幕）并新增**显示效果末级调节**（16 档亮度 + 切换淡入淡出 + 亮度条）；**阶段 2c**把交互改造为**蓝桥风格**：**拨码 SW1~SW4 直选场景**（与按键完全解耦）、**KEY1 循环功能模式**（图片/亮度/分辨率）、**KEY2/KEY3 对当前模式参数减/加**，并用**8 位数码管**统一显示「场景号/参数值/模式号/分隔符」；**阶段 2d**把 dev_sim 分支的会议/抢答/应急三场景仿真**移植为真汉字字库 OSD**——会议（公告翻页+运行时长+滚动会务提示）、抢答（**4 路外扩抢答台并行仲裁**+倒计时）、应急（红条闪烁+警示三角图标+滚动疏散字幕）；**阶段 2e（当前）**：①**一卡四区**——迎新/会议/抢答/应急**各有独立素材分区**（应急不再冻结上一场景画面，改为播本区告警素材）；②**自动轮播 ↔ 手动单张**切换（数码管第 8 位 `A`/`H` 提示；※ 最初设计是用 KEY4 独立切换，本轮已**收敛进模式0**，见下方加固 ⑧）；③**分辨率调节真做**——新增**双线性插值缩放引擎** `bmp_scale.v` 串入 TF→SDRAM 写通路，8 档 25%~300% 实时生效。

**本轮加固（2026-09-16 画质/仲裁/交互）**：④**场景仲裁改「应急最高 + 无应急时先触发先锁定」**（原为 `SW4>SW3>SW2>SW1` 静态优先级）；⑤**按键消抖重写**——统一「以消抖后电平为唯一基准 + 连续 10ms 偏离才采纳」，修掉偶发失灵（长按/连按/抖动都不丢键、不重复）；⑥**画质修复**——`bmp_scale` 的 100% 档改**真·1:1 旁路**（不重采样，与原图逐像素一致），并把插值长组合链拆成 **4 级流水**：原实现从行缓存到 `out_data` 是 22.3ns / 16 级逻辑，跑在 100MHz(10ns) 域 → TD 报 **-12.444ns 建立违规、out_data 全 24 位为失败端点**，实机插值像素会被采到未稳定的值 = **画面彩色噪点**；⑦**操作提示 HUD**——调**分辨率**弹 8 档青条、调**亮度**弹 16 档金条、切**轮播/手动**弹绿/橙状态卡，均「变化即弹、30 帧后自动消失」（与既有亮度条同风格）；⑧**交互收敛（切图并入模式0）**——原「按 KEY4 进手动后 KEY2/KEY3 才是上一张/下一张」有个真歧义：若当前停在**亮度模式**，按 KEY4 只翻了 `pic_manual`、`mode` 仍是 1，此时按 KEY2/KEY3 **调的还是亮度**（屏上却显示"手动"）。现改为：**切图作为 KEY1 模式循环里的模式0（与亮度同级）**——模式0 内 KEY3=下一张（并自动转手动、停自动计时）、KEY2=上一张（已在第1张时回自动）、离开模式0 自动回自动轮播；**KEY4 释放**（顶层 C1 引脚保留备用）。

## 功能特性

- TF 卡 SPI 读取 640×480 / 24bit 非压缩 BMP，解析文件头后写入 SDRAM 帧缓存
- HDMI 实时输出 VGA 分辨率画面
- **上电自动轮播**：无需按键触发，自动扫描并循环显示多张图片
- **蓝桥风格交互**（阶段 2c/2e）：先按 `KEY1` 选功能模式、再用 `KEY2/KEY3` 改当前模式参数（**与场景选择完全无关**）
  - `KEY1`=功能模式循环 `0图片/切图→1亮度→2分辨率→0`
  - `KEY2`=当前模式参数 **减**、`KEY3`=当前模式参数 **加**（同一时刻只有一个模式生效 → 三者互斥，不会串）
    - 模式0：`KEY3` **下一张**（并自动转入手动单张、停自动计时）/ `KEY2` **上一张**（已在第 1 张时改为**回自动轮播**）
    - 模式1：亮度 0..15；模式2：缩放档 0..7
  - **KEY4 已释放**（顶层 C1 引脚保留备用）：原「自动↔手动」不再需要独立键——**在图片模式里按 KEY2/KEY3 切图本身就是手动动作**，彻底消除「屏上卡显示手动、按 KEY2/3 却在调亮度」的模式歧义
  - 自动轮播的进出：刚进模式0（上电/切场景/从别的模式切回来）= **自动轮播**；按 KEY3 转手动；离开模式0（去亮度/缩放）自动回自动轮播；场景切换强制回自动轮播
- **一卡四区**（阶段 2e）：迎新/会议/抢答/应急**四个场景各播各自的扇区区间**（`Z_WEL/Z_MEET/Z_QUIZ/Z_ALARM`），切场景即按表重载扫描区间；**应急是独立第 4 分区**（播告警素材），不再是「冻结上一场景画面」
- **分辨率真做：双线性插值缩放引擎**（阶段 2e）：`bmp_scale.v` 串在 **TF→SDRAM 写通路**（`sd_card_bmp → bmp_scale → frame_read_write`），可分离「先水平后垂直」双线性插值（Q16 坐标映射 + Q8 权重 + 8bit 饱和钳位），**8 档 25%/33%/50%/67%/100%/150%/200%/300%**；缩小档图像水平居中、垂直顶部对齐（下方留黑），放大档按中心裁剪；改档由 `res_chg_pl` 触发**原地重读当前图**，约 0.3s 后画面按新档位重画（写通路 8 拍/像素节流防写 FIFO 溢出）；**100% 档为真·1:1 旁路**（不进插值状态机，源像素一拍不差直通，与原图逐像素一致）；插值运算已拆成 **4 级流水**（原 22.3ns 组合链在 100MHz 域违规 → 彩色噪点），图像区实际 12 拍/像素，仍远小于 SPI 供数 ≈96 拍/像素
- **拨码选场景（先触发先锁定 + 应急最高）**：SW1/SW2/SW3 分别选迎新/会议/抢答，**以先被拨上的那个为准并锁定**（之后拨上的其它场景不抢占；持锁场景被拨回时让给仍开着的优先者 `SW1>SW2>SW3`）；**SW4 = 应急最高优先级电平直通**（拨上即切、拨回即解，应急期间拨动普通 SW 只更新锁定权、不改画面）；四个全关=首页菜单引导态
- **首页菜单 OSD**（阶段 2a，V2 全屏矢量）：上电/无锁时**整帧由 OSD 自绘**——深藏青全屏底 + 2×放大金色下划线大标题 + 4 张场景卡（左侧彩色强调块/描边/2×卡标题/1×副标题）+ 底部黑色滚动宣传语条（每帧左移 1px，320px 无缝循环）。**菜单下不再透传/轮播任何背景照片**（16×16 点阵字库，片内 BRAM 自动生成，零素材依赖=最稳）
- **应急红条 OSD**（阶段 2a）：应急时顶部 52 行叠加红色警示条，最高优先级、不整屏清切换
- **迎新信息 OSD**（阶段 2b）：仅 `welcome_en`（SW1 迎新锁定且非应急）时叠加——顶部金底 50% 欢迎语横幅、左下「报到地点」卡（75% 衬底+蓝强调块）、右下「联系方式」卡（+青强调块）、底部 20 格滚动报到流程字幕（每帧左移 1px）；**非 OSD 区域原样透传背景照片**
- **场景切换淡入淡出**（阶段 2b）：菜单↔场景由 `menu_active` 边沿触发，alpha 逐帧降黑（每帧 -64，半程 4 帧）→ 等底层新分区图写完（`img_busy` 释放/超时 45 帧兜底）→ 逐帧淡入恢复；**应急期间强制不淡出**（最高优先级即刻响应）
- **16 档亮度调节 + 亮度条**（阶段 2b/2c）：**模式1**下 `KEY3` 增 / `KEY2` 减，默认 8 档=×1.0；档位增益 `g=64+L*8`（0.5×~1.44×），乘加取整+饱和钳位；档位变化时左上角弹 16 档图形条（金=已生效，保持 30 帧后自动隐藏）
- **应急独立分区**（阶段 2e）：SW4 打开→切到**第 4 分区（应急告警素材）**轮播，底层不再冻结上一场景画面；拨回 SW4 自动回到拨码所选场景分区（分区重载在 `S_IDLE/S_HOLD` 安全边界执行，帧写不中断）
- **会议场景 OSD**（阶段 2d，SW2）：顶部金线大标题条「校园会议信息公示」+ 右上「已运行 HH:MM:SS」时长面板（数字带 RTL 绘制冒号）+ 中部公告面板（**4 页公告每 480 帧自动翻页**，含金色页码数字 1~4）+ 底部滚动会务提示字幕
- **抢答场景 OSD**（阶段 2d，SW3）：顶部标题条「抢答进行中」+ 中部状态面板（等待开始 / 抢答中 / **选手N号抢答成功** / 时间到无人抢答，随 `quiz_ctrl` 状态切换）+ 2× 倒计时数字与「秒」+ 底部滚动抢答须知
- **4 路抢答台并行仲裁**（阶段 2d）：经 **2×40Pin 外扩口**接 4 路选手键 + 开始键 + 复位键；统一 100MHz 时钟域同步采样 + 20ms 消抖 → **片内硬件并行仲裁**（同拍多路按 `1>2>3>4` 预定义优先级裁定，锁存胜者后忽略后续键，「先到先得」），BCD 倒计时 10s 归零判超时
- **应急告警画面增强**（阶段 2d，SW4）：顶部 52 行警示红条 **4Hz 闪烁** + RTL 绘制警示三角图标 + 深红衬底标题「紧急情况 请立即疏散」+ 底部滚动疏散告警字幕（按项目决策**只做画面告警**，不加蜂鸣器/LED 声光）
- **8 位数码管统一显示**（阶段 2c/2e）：第1位=场景号 0..3；第2~4位=当前模式参数（模式0 手动第N张/0=轮播，模式1 亮度，模式2 缩放档，前导零熄灭）；第5位=功能模式号 0/1/2；第6/7位=`-` 分隔符；**第8位=轮播状态 `A`(自动)/`H`(手动)**
- 修正 BMP 自底向上存储导致的画面上下颠倒
- 严格 BMP 头校验 + 图片计数回卷，避免把卡内残留/已删除数据误判成图片（防花屏）

## 编译与烧录

1. 用安路 TD EDA 打开工程文件 `pic_sdram.al`。
2. 顺序执行：综合（Synthesize）→ 布局布线（Place & Route）→ 生成比特流（Generate Bitstream）。
3. 将 TF 卡插入开发板，用下载线把生成的比特流固化到板内配置 Flash（上电自动运行，无需 PC 重下载）。

> 说明：SDRAM 控制器与 HDMI 发送器为安路官方加密网表（`*.enc.v / *.enc.vhd`），仅能在 TD EDA 中使用；PLL / FIFO 为 TD 生成的 IP 核。

### BMP 属性要求（严格校验，缺一项就扫不到）

| 项目 | 要求 |
| ---- | ---- |
| 格式 | Windows BMP，**头 54 字节**（14 文件头 + 40 信息头） |
| 分辨率 | **640×480** |
| 位深 | **24bit 真彩色**（RGB888），**非压缩**（BI_RGB，不可 RLE） |
| 方向 | **正高度（bottom-up，标准）**；「自上而下」（负高度）会被拒绝 |
| 文件大小 | **正好 921654 字节** = 54 + 640×480×3（不可带 ICC/调色板/多余字节） |
| 位置 | 卡**根目录**（不要放子文件夹） |
| 磁盘 | FAT32（或 exFAT）**完整格式化**，簇大小 **≥ 4KB** |

> **为什么必须整 921654 字节**：程序按裸扇区扫描、不解析文件系统（见 [bmp_read_auto.v](file:///e:/FPGA/ALST/fpgapmzs/src/bmp_read_auto.v#L187-L192) 的严格校验），长度不符会被直接滤掉。
> **为什么卡要完整格式化 + 簇 ≥ 4KB**：扫描是**每 8 个扇区跳一次**（4096B 步进）。一张图 921654B ≈ 1801 扇区，不是 8 的倍数；只有文件系统按 ≥4KB 簇分配（占 1808 扇区）时，每张图起点才天然落在 8 扇区格点上，才能被逐张命中。
> **为什么必须完整格式化**：删除文件时 FAT 只清目录项，像素数据仍残留在卡上，会被扫描器误认成图 → 花屏。

### 推荐生成方式

用 Python/PIL 另存（产物天然满足全部要求）：`Image.open(x).convert('RGB').save('wel_1.bmp')`；也可用画图另存「24 位位图」，但需校验文件长度。

拷盘前自检（把盘符改成你的卡）：

```python
import struct, os, glob
for f in sorted(glob.glob(r'F:\*.bmp')):
    d = open(f, 'rb').read(54)
    L = os.path.getsize(f)
    w = struct.unpack('<I', d[18:22])[0]
    h = struct.unpack('<i', d[22:26])[0]
    b = struct.unpack('<H', d[28:30])[0]
    ok = (d[:2] == b'BM' and L == 921654 and w == 640 and h == 480 and b == 24)
    print(f, L, w, h, b, 'OK' if ok else '*** 不合格')
```

### 一卡多区：操作流程

1. **做图**：迎新/会议各 2~3 张、抢答/应急各 1~2 张，全部通过上面自检。建议按场景加前缀并按顺序复制：`wel_1.bmp…` / `meet_1.bmp…` / `quiz_1.bmp…` / `alarm_1.bmp…`。
2. **完整格式化**卡（取消「快速格式化」），FAT32，簇 ≥ 4KB。
3. **按场景顺序拷图**到卡根目录（迎新 → 会议 → 抢答 → 应急），中途不要插别的文件。
4. **实测扇区并生成分区表**（在**管理员权限**终端，物理盘读取需要管理员）：

   ```
   python tools/find_bmp.py --drive F
   python tools/find_bmp.py --drive F --start 126000 --end 400000 --sizes 2,2,2,2 --names WEL,MEET,QUIZ,ALARM
   python tools/find_bmp.py --drive F --all          # 只列合格图, 不分段
   ```

   工具会输出三部分：① 合格图清单（含 8 扇区对齐检查）；② 按 `--sizes` 切段的 `START/WRAP/IMGS`，并**直接打印可粘贴进 [top.v](file:///e:/FPGA/ALST/fpgapmzs/src/top.v#L85-L99) 的 localparam**；③ 「命中 BM 但不合格」的扇区（排查残留/花屏）。

   参数：`--start` 起始扇区（默认 16000，自动 8 扇区对齐）、`--end` 结束扇区（`0`=自动，连续 1GB 无命中即停）、`--sizes` 各段张数（默认 `5,5,5`）、`--names` 各段名（默认 `WEL,MEET,QUIZ`，四区用 `WEL,MEET,QUIZ,ALARM`）。

5. **改 [top.v](file:///e:/FPGA/ALST/fpgapmzs/src/top.v#L85-L99) 分区表**：把工具输出的 localparam 覆盖 `Z_WEL/Z_MEET/Z_QUIZ/Z_ALARM` 四组（`Z_MENU` 直接复用迎新区值即可——菜单态整帧由 OSD 自绘覆盖）。
6. **TD EDA**：综合 → 布局布线 → 生成比特流 → **下载到配置 Flash**（上电即运行）。

> `WRAP` 语义：扫描中 `addr >= WRAP` 即回卷 `START`。故每段取「下一段首张图起点」最安全（绝不串段），末段取「本段末张 + 8 扇区」。工具已按此规则算好。
> 换卡/重新排布素材后，**必须重跑第 4 步并同步 `Z_*`**（FAT 分配顺序不可预测）。

## 场景选择与素材分区（阶段二 / 2c 直选）

场景**只由板载拨码 SW 决定**（静态电平，`scene_control` 内两级同步 + 10ms 消抖；`SW_ACTIVE_LOW=1` 即 ON=拉低有效）。按键 KEY1~KEY3 属于**场景内的功能参数调节**（见下方人机交互），与场景切换完全解耦：按键不会进入/退出场景，也不会触发应急。

| 开关 | 场景 | 生效 |
| ---- | ---- | ---- |
| `sw[0]` / SW1 | 场景 0 迎新 | 拨上即进入（**先拨上者得锁**；同为候选时优先级最低） |
| `sw[1]` / SW2 | 场景 1 会议 | 拨上即进入（**先拨上者得锁**；同为候选时优先于 SW1） |
| `sw[2]` / SW3 | 场景 2 抢答 | 拨上即进入（**先拨上者得锁**；同为候选时优先于 SW1/2） |
| `sw[3]` / SW4 | 场景 3 应急（**最高优先级**） | **电平直通**：拨上立即切应急，拨回即解除，无需清除键 |

规则：

1. **先触发先锁定（普通场景）**：SW1/SW2/SW3 中**先被拨上**的那个场景获得锁定权，之后拨上的其它普通场景**不抢占**（画面保持不动）；持锁场景被拨回时，锁定权让给**仍开着的**场景（此时按 `SW1>SW2>SW3` 定序）。
2. **全部拨回=菜单引导态**：三个普通 SW 全关且无应急 ⇒ `menu_active=1`（**上电默认**，等拨码选择）；回菜单后重新拨上一路即可拿到锁定权。
3. **应急最高优先级（绝对抢占）**：SW4 打开 → `emergency=1`，立即切到第 4 分区（应急告警素材）+ 应急 OSD，**压倒任何锁定中的普通场景**；应急期间拨动普通 SW 只更新「锁定权」，不改画面；SW4 拨回 → 立即恢复当前锁定权对应的场景分区。

### 场景状态与素材加载链

| 状态 | scene_id | latch_sw | menu_active | 行为 |
| ---- | -------- | -------- | ----------- | ---- |
| 菜单 | 0 | 0 | 1 | OSD 全屏矢量菜单（不依赖素材，上电默认） |
| 迎新 | 0 | 1 | 0 | 迎新素材分区轮播，叠加迎新信息 OSD |
| 会议 | 1 | 2 | 0 | 会议素材分区（当前过渡素材）+ 会议 OSD（公告翻页/运行时长/滚动提示） |

| 应急 | 3 | 4 | 0 | **第 4 分区（应急告警素材）轮播** + 应急 OSD（闪烁红条/警示三角/滚动疏散告警，覆盖所有场景） |

切换链：`scene_control`（latch_sw/emergency/menu_active）→ top.v 按 `latch_sw` 查 Z_* 分区表 → `zone_load`(=scene_change_pulse) → `bmp_read_auto` 在安全边界（`S_IDLE`/`S_HOLD`）重载扫描区间 → 新场景素材写入帧缓存。**应急也是独立分区（`Z_ALARM`，阶段 2e）**：拨上 SW4 即重载到应急素材区轮播（不再是「冻结上一场景画面」）；拨回即按 `latch_sw` 恢复原场景分区。三场景 OSD 使能：`meeting_en=(latch_sw==2)&&~emergency`、`quiz_en=(latch_sw==3)&&~emergency`、`alarm_en=emergency`。

### 人机交互（阶段 2c/2e，蓝桥风格：先选功能模式，再用加减键改参数）

| 按键 | 引脚 | 职责 |
| ---- | ---- | ---- |
| `KEY1` | A2 | 功能模式循环切换，每按一次 +1：`0图片/切图→1亮度→2分辨率→0` |
| `KEY2` | B2 | **当前模式参数 减** |
| `KEY3` | B1 | **当前模式参数 加** |
| `KEY4` | C1 | **已释放**（顶层引脚保留备用，不接逻辑） |

> 按键与场景无关：无论在哪个场景（SW 拨到哪一档），KEY1~KEY3 都按同一套「模式/参数」语义工作。

各模式参数：

- **模式 0 图片/切图**：`KEY3`=**下一张**、`KEY2`=**上一张**（按下的同时**自动转入手动单张**、停止自动轮播）；已在第 1 张时再按 `KEY2` → **回到自动轮播**（参数归 0）；**离开模式0（按 KEY1 去亮度/分辨率）也自动回自动轮播**；场景切换同样强制回自动轮播。**每次状态变化屏上弹状态卡**：绿=自动轮播 / 橙=手动单张（30 帧后消失）。
- **模式 1 亮度**：参数=亮度档 0..15（默认 8），`KEY3` + / `KEY2` -，到边界钳位；**变化时左上角弹 16 档金色亮度条**（30 帧后消失）。
- **模式 2 分辨率**：参数=缩放档 0..7（`25%/33%/50%/67%/100%/150%/200%/300%`，默认 4=100%），`KEY3` + / `KEY2` -；改档立即触发 `res_chg_pl` → `bmp_read_auto` **原地重读当前图**（不切图序号），约 0.3s 后按新档重画；**变化时左上角弹 8 档青色缩放条**（30 帧后消失）。

> **为什么三个功能共用 KEY2/KEY3 却不冲突**：三条去向的门控用的是**同一个 `mode` 寄存器**（`mode==0` 才切图、`==1` 才调亮度、`==2` 才调缩放），同一时刻只有一个模式成立 → 最多一条生效，天然互斥。这也是上一版把 KEY4 释放、把「切图」并进模式0 的原因（旧版要 KEY4 先翻 `pic_manual`，若当时停在亮度模式，按 KEY2/3 调的仍是亮度）。

> **三块操作提示 HUD**（阶段 2e 加固，与亮度条同风格，均由 `display_adjust.v` 末级绘制、保持 `30` 帧后自动消失）：
> | HUD | 触发 | 位置/样式 |
> | ---- | ---- | ---- |
> | 金色亮度条 | `bri_level` 变化 | 左上 x8..144 / y4..11，生效格金色、空槽深灰 |
> | 青色缩放条 | `res_level` 变化 | 左上 x8..144 / y16..23（8 档） |
> | 轮播状态卡 | `pic_manual` 翻转 | 左上 y28..51，绿=自动 `A` / 橙=手动 `H` |
> 三个触发源都来自 `sd_card_clk` 域，模块内**两级同步后取变化沿**武装，因此与 OSD 同在 `video_clk` 域绘制、不会撕裂。

### 数码管显示布局（8 位）

| 位 | 含义 |
| -- | ---- |
| 第 1 位 | 场景号 `0/1/2/3`（scene_id） |
| 第 2~4 位 | 当前模式参数值（模式0：0=轮播 / N=手动第 N 张；模式1：亮度；模式2：缩放档），**前导零熄灭** |
| 第 5 位 | 功能模式号 `0/1/2` |
| 第 6、7 位 | 固定短横线 `-` 分隔符 |
| 第 8 位 | **轮播状态 `A`（自动）/ `H`（手动）**（阶段 2e） |

## 阶段 2a：首页菜单 / 应急 OSD

视频链路（阶段 2a~2c；2d 在 `osd_welcome` 与 `display_adjust` 之间插入 `osd_scene`，见下节）：`video_timing_data → frame_read_write → video_delay → osd_engine → osd_menu → osd_welcome → display_adjust → hdmi_tx`

- `osd_engine`（video_clk≈25.175MHz 域）：在已对齐像素流上重建 0 基坐标 (0~639, 0~479)，与 de/data 严格同拍，供上层叠加引用。
- `osd_menu`：**菜单态**（`menu_ok`）**整帧自绘全屏矢量菜单**——不透传、不轮播底层照片，因此**菜单不依赖任何 TF/SDRAM 素材**，上电即显示、显示问题与素材无关：
  - 深藏青全屏底（0x0A1220），顶部 2× 放大标题「校园多功能信息终端」+ 金色强调下划线；
  - 4 张场景卡（x70~570、高 80、距 10，top 80/170/260/350）：左侧 8px 彩色强调块（蓝/青/橙/红，对应迎新/会议/抢答/应急）、2px 描边、2× 卡标题、1× 副标题；
  - 底部 42 行黑色宣传语条（y438~479）承载 20 格滚动文字（每帧 vsync 相位 +1，320px 无缝左移）。
  - **应急态**（`emerg_ok`）顶部 52 行红色警示条（最高优先级，覆盖所有场景）。`menu_en/emerg_en` 为跨时钟域电平（sd_card_clk→video_clk），模块内两级同步后使用。
- 字库 `osd_font_rom.v`：片内 BRAM（16bit×**4608** 深 ≈72Kbit，阶段 2d 扩容后）存全部文字带 16×16 点阵字形，由 `tools/gen_osd_font.py` 自动生成；2× 放大字形仍存 16×16 原模，放大由 RTL 行列复制完成。**注意：例化模块内 `rom_addr` 位宽须与 ROM `ADDR_W(13)` 一致**，否则 ModelSim 高位补 X 读出 `mem[X]`。

> 文字带几何/墨点（gen 脚本 stdout = osd_menu.v 几何表，一处改两处同步）：TITLE base0/N9/2×/ty28/gx176；CT0~3 base144/208/272/336 N4 2×；TG0~3 base400/512/624/736 N7 1×；MARQ base848 N20 1×。静态采样点与滚动带宽均可在 `python tools/gen_osd_font.py` 输出中核对。

### 修改菜单文案/几何（务必三处同步）

1. 改 `tools/gen_osd_font.py` 的 `BANDS` 表文本与各区几何参数；
2. 同步改 `src/osd_menu.v` 顶部**几何表**（rid2/rid3 行窗、gx/ty/N/base、颜色常量）；
3. 重跑 `python tools/gen_osd_font.py` 重新生成 `src/osd_font_rom.v`。

> 像素级断言采样点（每文字带 1 ON/1 OFF + 矢量特征点）来自脚本 stdout，改文案后需同步 `tb/tb_osd_menu.v`。

## 阶段 2b：迎新信息 OSD / 显示效果调节

叠加引擎在 `osd_menu` 之后串行接入（每级恒定 3 拍延迟 + 同拍坐标透传下游）：

- `osd_welcome`：仅 `welcome_en`（`latch_sw==1` 迎新锁定且非应急）时叠加，其余场景纯透传：
  - 顶部欢迎语**金底半透明横幅**（bg>>1 混 50%）承载 2×「欢迎新同学...」大字（白）；
  - 左下「报到地点」信息卡、右下「联系方式」信息卡：**深底 75% 衬底**（bg 75%=`bg - (bg>>2)`）承载 1× 白标题 + 1× 内容小字，卡左侧 8px 强调块（蓝/青），带淡描边；
  - 底部 42 行**黑色滚动流程字幕带**（25% 透显底 `bg>>2`）承载 20 格报到流程文字（亮橙），每帧相位 +1、320px 无缝左移；
  - 文字/卡的**背景均与真实照片混合**（真 Alpha），非 OSD 像素 100% 透传保持背景照片。
- `display_adjust`（末级，对整帧生效）：
  - **亮度**：`g=64+L*8`（L 0..15），`out=clamp((pix*g+64)>>7)`；`alpha==255` 时直通（稳态与原像素逐位一致）；
  - **淡入淡出**：4 态 FSM（FIDLE/FOUT/FBLCK/FIN）。`menu_active` 翻转经两级同步产生粘性事件 `menu_evt`，帧边界（vs 上升沿）消费：淡出每帧 -64 到 0 → FBLCK 等 `bmp_busy`（=img_busy，`~sd_init_done|zone_pend|S_FIND|S_READ_WAIT|S_READ`）释放或 45 帧超时 → 淡入每帧 +64 → FIDLE；`emerg` 期间强制 alpha=255、丢弃挂起事件（应急不淡出）；
  - **三块操作提示 HUD**（同风格，均由跨域同步后的**变化沿**武装，`BAR_HOLD_FRAMES(30)` 帧后自动消失；每帧 vs 边沿 -1，武装当帧即扣 1 故实际连显 29 帧）：
    - 亮度条：`lvl_s` 变化 → 盒 x8..144×y4..11（描边 286px、内区 135×6），生效 `L*9px` 金、未生效深灰；
    - 缩放条：`res_s` 变化 → 盒 x8..144×y16..23，8 档，生效 `k*16px` **青**（22D3EE）、未生效深灰；
    - 轮播状态卡：`man_s` 翻转 → 盒 x8..144×y28..51，绿（22C55E）=自动 / 橙（FFA028）=手动；
    - 三块 HUD 均为**固定色后叠**，不受亮度增益影响（避免调亮度时提示条自身变色）。
- `ui_key_ctrl`（sd_card_clk 100MHz 域，阶段 2c）：按键经 **10ms 消抖 `ui_key_dbnc`**（两级同步 + 「以消抖后电平为唯一基准 + 连续偏离才采纳」计数器，触发沿取自消抖后电平）；`KEY1` 循环功能模式（0图片/切图、1亮度、2缩放）；**模式1** 下 `KEY3`/`KEY2` 增/减亮度档并钳位 0..15（默认 8），驱 `display_adjust.bri_level`；**模式2** 下发 `res_chg_pl`（改缩放档）；**模式0** 由切图动作自动维护 `pic_manual`（转手动/回自动）。三类输出分别驱 `display_adjust` 对应 HUD。**KEY4 已释放**（不接逻辑）。

> ⚠ 色值语义：OSD 颜色常量（金 `0xFFD24A`、字 `0xF5FDFF` 等）为**半透明/自绘素材色**，实际出屏色=常量与底层照片按 Alpha 混合。逐色校验的**期望混合值**见 `tb/tb_osd_welcome.v` 顶部（C_GOLDM/C_CARDM/C_DARKM/EX_* 像素数）与 `tb/tb_display_adjust.v`（恒灰 P=0x808080 推导档位输出，如 L8→0x80、L12→0xA0）。

## 阶段 2d：会议 / 抢答 / 应急三场景（真汉字 OSD）

来源：把 GitHub `dev_sim` 分支上新加的会议/抢答/应急三套场景仿真（原为纯色块占位 Overlay）**移植为真汉字字库版**，并合并为单一模块共用一片字形 ROM（省资源、低功耗）。

视频链路（当前，2d）：`video_timing_data → frame_read_write → video_delay → osd_engine → osd_menu → osd_welcome → osd_scene → display_adjust → hdmi_tx`

- `osd_scene`（video_clk≈25.175MHz 域，三场景互斥、使能全 0 时纯透传；管线与 `osd_menu`/`osd_welcome` 同构，恒定延 3 拍 + 坐标透传）：
  - **会议**（`meeting_en`）：顶部金线大标题条「校园会议信息公示」；右上「已运行 HH:MM:SS」时长面板（`run_hh/mm/ss` BCD，冒号由 RTL 绘制）；中部公告面板 4 页文字每 `PAGE_FRAMES=480` 帧自动翻页（金色页码数字 1~4）；底部滚动会务提示字幕。
  - **抢答**（`quiz_en`）：顶部标题条「抢答进行中」；中部状态面板随 `quiz_ctrl.qstate` 显示「等待开始 / 抢答中 / 选手N号抢答成功 / 时间到无人抢答」；2× 倒计时数字 + 「秒」；底部滚动抢答须知。
  - **应急**（`alarm_en`）：顶部 52 行警示红条以 **4Hz 闪烁**（`BLINK_DIV`=125ms@25.175MHz）+ RTL 绘制的警示三角图标 + 深红衬底标题「紧急情况 请立即疏散」+ 底部滚动疏散告警字幕。**只做画面告警，不加蜂鸣器/LED 声光**（项目决策）。
- `quiz_ctrl`（sd_card_clk 100MHz 域）：
  - 4 路选手键 `player_raw` 两级同步 + 20ms 消抖 → **片内硬件并行仲裁**：同一采样周期内多路有效按 `player1>player2>player3>player4` 预定义优先级裁定，**锁存胜者后忽略后续按键**（先到先得）；「多路输入按统一时钟域同步采样 + 并行仲裁」，非机械「谁绝对先按下」。
  - `start_raw`=开始/下一轮（抢答中再按=重开本轮计时）；`clear_raw`=复位回等待开始；BCD 倒计时 `TIME_SEC=10` 秒归零判「时间到」。
  - 状态机 `0=等待开始 / 1=抢答中 / 2=已锁定 / 3=超时`；`en=0`（非抢答场景或应急）强制回等待开始、清胜者、选手键完全无效。
- 抢答台输入经 **2×40Pin 外扩口**接入，引脚见下方「外扩口（抢答台）」。

> ⚠ 会议/抢答/应急场景的底图仍需 640×480 / 24bit 非压缩 BMP 素材（按 `Z_MEET/Z_QUIZ` 分区排布，当前为过渡占位）；菜单/应急 OSD 本身零素材依赖。
> 几何/文案唯一数据源 = `tools/gen_osd_font.py`（改文案须同步 `src/osd_scene.v` 几何表并重跑生成，再跑 `tb_osd_scene.v` 像素级回归）。

| ---- | ------ | ---- | ---- |
| `quiz_btn[0]` | GPIOA0 | H13 | 1 号选手抢答键 |
| `quiz_btn[1]` | GPIOA1 | N16 | 2 号选手抢答键 |
| `quiz_btn[2]` | GPIOA2 | N14 | 3 号选手抢答键 |

## 开关/按键分工（当前）

| 信号 | 引脚 | 职责 | 备注 |
| ---- | ---- | ---- | ---- |
| `sw[0]` | C8 | SW1=场景 0 迎新 | ON=拉低有效；先拨上者得锁 |
| `sw[1]` | C7 | SW2=场景 1 会议 | 同为候选时优先于 SW1 |
| `sw[2]` | C6 | SW3=场景 2 抢答 | 同为候选时优先于 SW1/2 |
| `sw[3]` | C5 | SW4=场景 3 应急 | 最高优先级（绝对抢占），拨回即解除 |
| `key1` | A2 | 功能模式循环 `0图片/切图→1亮度→2分辨率→0` | 消抖 10ms |
| `key2` | B2 | 当前模式参数 **减** | 模式0 上一张（首张时回自动）/ 模式1 亮度- / 模式2 档位- |
| `key3` | B1 | 当前模式参数 **加** | 模式0 下一张（并转手动）/ 模式1 亮度+ / 模式2 档位+ |
| `key4` | C1 | **已释放**（保留引脚，不接逻辑） | 原「自动↔手动」已并入模式0切图 |
| `quiz_btn[3:0]` | H13/N16/N14/G14 | 抢答台 4 路选手键（**仅抢答场景有效**） | 外扩口 GPIOA0~A3，上拉/按下低 |
| `quiz_start` | H15 | 抢答台开始/下一轮 | 外扩口 GPIOA4 |
| `quiz_reset` | F14 | 抢答台复位/清除 | 外扩口 GPIOA5 |

> 复位：**无物理复位引脚**，改用上电自动复位（POR，约 10.5ms）——`top.v` 内 `por_cnt[19:0]` 计数产生。
> 解耦：场景=SW 决定；KEY1~KEY3=场景内功能调节，二者互不影响。

## 现场演示方法

1. 上电 → 默认**全屏矢量菜单态**（四个 SW 全关）：整屏自绘菜单（大标题+4 场景卡+底部滚动宣传语，**无背景照片轮播**），数码管第 1 位显示场景号、第 5 位显示模式号、第 6/7 位为 `-`、第 8 位 `A`（自动）。
2. 拨 **SW1** → 进入场景 0 迎新，菜单消失，**迎新区素材**（2 张）轮播（叠加欢迎语横幅/报到地点卡/联系方式卡/滚动报到流程字幕）。
3. **KEY4** 切到**手动单张**（数码管第 8 位变 `H`，画面停在第 1 张不再自动翻）→ 按 **KEY1** 切到**模式 0（图片）**，按 **KEY3/KEY2** 手动下一张/上一张（数码管第 2~4 位显示当前图序号）；再按 **KEY4** 显式切回**自动轮播**（第 8 位回 `A`）——这就是「轮播 vs 手动」的显式区别。
4. 按 **KEY1** 切到**模式 1（亮度）**，按 **KEY3/KEY2** 增/减亮度档（左上角弹亮度条，数码管显示亮度值）。
5. 按 **KEY1** 切到**模式 2（分辨率）**，按 **KEY3/KEY2** 改缩放档（数码管显示档位；画面按 `25%…300%` 重画，缩小档居中留黑、放大档中心裁剪，约 0.3s 后生效）。
6. 拨 **SW2** → 切**会议场景**（**会议区素材** + 会议 OSD：标题条 + 右上运行时长 + 公告每 8s 翻页 + 底部滚动会务提示）；拨 **SW3** → 切**抢答场景**（**抢答区素材** + 抢答 OSD：状态面板/倒计时），经外扩抢答台按 `quiz_start` 开始 → 选手抢答 → 屏显「选手N号抢答成功」+ 锁存；`quiz_reset` 复位。**多场景同开时：无应急则以先拨上的那个为准并锁定，之后拨上的普通场景不抢占**（把持锁那路拨回，才让给仍开着的下一路）。按键操作与场景互不影响。
7. 拨 **SW4** → 立即切应急：**重载到第 4 分区（应急告警素材）**轮播 + 顶部闪烁红条（4Hz）+ 警示三角 + 滚动疏散告警；拨回 **SW4** → 自动恢复原场景分区；切场景/切回菜单可见淡出→淡入过渡（扩展 2/3/4 现场证据）。

> ⚠ 演示注意：菜单为全屏自绘、**不再展示背景照片**，因此赛题基础 1/2（TF 图→SDRAM→HDMI、手动/自动切换）的现场证据必须**拨入任一普通场景**（如 SW1 迎新）观看轮播来体现；菜单本身是扩展 1（OSD 图层/滚动字幕）的证据。材料照片需 640×480 / 24bit / 非压缩 BMP，按 `Z_WEL/Z_MEET/Z_QUIZ/Z_ALARM` 四区放入 TF 卡（菜单区素材已不再需要）。
> ⚠ 缩放档（模式 2）对**当前显示的那张图**生效：改档后 `reload_req` 原地重读同一张（图序号不变），因此可以在同一张图上直观对比 8 个档位。

| ---- | ------ | ---- |
| `SLIDE_INTERVAL` | `300_000_000` | 每张图停留周期数（100MHz≈3s） |
| `ZONE_START_SECTOR` | `126000` | 复位默认分区起点（菜单分区） |

阶段 2e 关键参数：

| 模块 | 参数 | 默认值 | 含义 |
| ---- | ---- | ------ | ---- |
| `bmp_scale.v` | `SRC_W` / `SRC_H` | `640` / `480` | 源图尺寸（写通路输入） |
| `bmp_scale.v` | `CANV_W` / `CANV_H` | `640` / `480` | 输出画布（必须与 SDRAM 帧一致，帧长/写地址/行翻转不用改） |
| `bmp_scale.v` | `scale_sel[3:0]` | 运行时 | 8 档：`0=25% 1=33% 2=50% 3=67% 4=100% 5=150% 6=200% 7=300%`（`cfg_dstw=SRC_W*n/d`） |

| `bmp_scale.v` | 输出节流 | 8 拍/像素 | 防写 FIFO(`wfifo_32_32_512`)溢出；`100%` 恒等档同样走该引擎 |

> `bmp_scale` 每帧输出恒定 `CANV_W×CANV_H` 个像素（图像区以外填黑 32'h0），因此**不改动** `frame_read_write` 的帧长 `307200`、写地址与行序翻转逻辑。
> ⚠ 缩放引擎的 3 行缓存要求「输出所需源行不能落后输入前沿超过 2 行」——缩小档必须顶部对齐（见 `bmp_scale.v` 文件头），仿真喂数速率须 ≥ 实机 SPI（≈96 拍/像素）。
