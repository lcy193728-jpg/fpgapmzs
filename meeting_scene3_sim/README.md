# 场景三 会议议程控制与计时管理

依据《应急信息发布终端版.docx》场景三开发，仅做独立模块 ModelSim 验证。
开发基准为 main 提交 `e888998`，原 `top`、`osd_scene`、`ui_key_ctrl`、
`hdmi_tx` 等源码和接口没有修改。`baseline` 三个文件原样来自该提交，
复用 `key_debounce`、`seg_scan`、`seg_decoder`，避免依赖 dev_sim 旧底层。
仿真模块入口为 `rtl/meeting_scene3.v`，不会自动接入现有上板工程。
`baseline` 只供独立仿真使用；队友在 main 工程中复用已有模块定义，
不要再次把 baseline 加入综合列表，以免模块重定义。

## 已实现

- MTG1 会议配置字节流解析：会议名、主办方、会场、四条字幕、1～16 项议程。
  每项含名称、发言人、1～5999 秒计划时间。配置错误时禁止开始。
- 七状态：0 IDLE、1 RUNNING、2 PAUSED、3 WARNING、4 TIMEOUT、
  5 SWITCH、6 FINISHED。支持超时正计时，上限 99:59。
- KEY1 开始/暂停/继续，KEY2 下一项，KEY3 上一项，KEY4 当前项重新计时。
  KEY2 长按直接结束，KEY4 长按回初始状态，长按不重复执行短按动作。
  沿用 main 的低有效按键、两级同步和消抖。短按在消抖后的释放沿执行，
  用于区分长短按；长按 1 秒触发一次。
- >60 秒绿色、≤60 秒黄色、归零后红色闪烁。跨过 60 秒仅提示一次；
  初始时长 ≤60 秒的议题在开始时提醒一次。超时提示两次。
- 当前/下一议题、发言人、下一项计划时间、序号、系统运行时间、整体进度条、
  初始议程总览（超过 8 项分两页）、四条循环滚动通知，固定背景 RGB 透传。
- 数码管同步显示 MM.SS（硬件没有独立冒号，分钟个位的小数点作分隔）。
- 独立告警输入两级同步、锁存、ALARM_CLEAR；输入有效优先于清除。
  告警冻结议题和计时并覆盖顶部，切换告警蜂鸣节奏。
  清除后显示“会议因告警暂停”，KEY1 才继续，保留不足一秒的计时进度。
- 蜂鸣器、48kHz 有效采样使能、16bit 有符号双声道 PCM。
  提醒为 1kHz 单鸣，超时为 600Hz 双鸣，告警重复鸣。

## 仿真复现

在本目录运行（无需修改 main 或接入 PLL/SDRAM/加密 HDMI IP）：

```powershell
./tools/run_sim.ps1
```

默认使用 `D:/altera/14.1/modelsim_ase/win32aloem/vsim.exe`。
`mti_copy.exe` 是文件辅助工具，不是仿真入口。
每次仿真创建独立时间戳目录，保存 transcript、WLF、波形窗口截图；
主流程和显示仿真另生成 PPM，可用 `tools/convert_frames.py` 转 PNG。
自动截图需要 Windows 交互桌面，显示 ModelSim 波形窗口片刻后关闭。
如果无交互桌面，脚本明确报错，已有 WLF 和日志仍保留。

| 测试 | 检查数 | 验证重点 |
| --- | ---: | --- |
| tb_meeting_scene3 | 45 | 配置异常、按键、计时、应急、长按、视频旁路 |
| tb_meeting_edges | 20 | 60秒边界、同拍暂停、切议题瞬间告警、短时议题、超时暂停 |
| tb_meeting_io | 10 | 2扇区读取握手、48k采样、一次/两次/重复音节奏 |
| tb_meeting_display | 18 | 10幅逐像素画面、真实字模与颜色、闪烁、滚动、同步对齐 |

最终四组共 93 项检查通过，编译和仿真均 0 Errors、0 Warnings。
测试缩短计时周期，功能秒不等于墙钟秒；正式实例默认计时域 100MHz，
每秒 100000000 拍，消抖 20ms。系统运行时间从复位计起，无 RTC。

## TF 配置与素材

`assets/meeting.json` 是人可读源文件；`tools/build_assets.py` 用黑体生成与
main 一致的 16×16、MSB 在左的真实汉字点阵和 MTG1 字节配置。
`meeting.bin` 为 TF 固定扇区镜像片段，`meeting.hex` 为仿真同源数据。
本包不写真实 TF 卡、不支持 FAT 文件名查找，沿用 main 固定扇区方式。
`rtl/meeting_sd_reader.v` 接口与 main `sd_card_top` 的扇区握手一致，
提供 cfg_start/valid/data/last。示例配置为两扇区；最多16项需要三扇区。
START_SECTOR 示例值必须由队友依真实卡布局确认，不能直接覆盖 BMP 区。

重新生成配置和字库：

```powershell
# 使用含 Pillow 的 Python
python tools/build_assets.py
```

格式：`MTG1` 四字节魔数 + 议程数1B + 7段各40B文字 + 每议程62B
（秒数大端2B、名称40B、发言人20B），补零到512字节。
字符字节是 `encoding.json` 中的字模索引，不是 UTF-8。
任意新增字需要重新生成字库；在既有字库字符集合内调整议程及文案，
可以仅替换配置。当前字库在 HDL 中初始化，尚未做 TF 动态字库装载。
会议名 32px 字号，建议≤18字；议题标题建议≤18字，其他字段注意屏幕宽度。

## 队友集成时的边界

本次独立仿真使用一个时钟域，视频接口沿用 RGB888、12位坐标及同步信号风格，
全组输出延迟一拍。上板时控制域100MHz与像素域约25.175MHz不同：
必须通过完整状态/文字快照握手或异步FIFO传输，不能直接将多位文本和时间
各自两级同步。共享 TF SPI 控制器需仲裁；禁止两个 SPI master 同时驱动引脚。
背景从现有帧缓存预载一次，会议中不轮播。不修改冻结的主工程。

**HDMI 音频限制**：main 的 `src/hdmi/hdmi_tx.vhd` 实例化 `DVITransmitter`，
只有视频端口。这里验证了提示音 PCM 与蜂鸣器生成，没有声称现有 HDMI 已能发声。
队友需选用支持音频的发射通路，接收 sample_valid/pcm_l/pcm_r，并处理音频 CDC。
本次未验证 HDMI 音频数据岛封包、实际 SPI 卡、电气连接、资源/时序收敛或上板效果。

应急顶部覆盖只是会议模块的联动验证；完整场景四类型、地点和疏散指令仍由
已有告警层负责，不重写场景四。告警清除输入应由上层提供同域单周期脉冲。
新增模块没有赋予普通场景优先级，也没有改动现有场景选择约定。
