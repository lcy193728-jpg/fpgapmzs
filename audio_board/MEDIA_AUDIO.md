# 场景联动音频实现与上板验收

依据：《媒体音调联动pcm_media_tone设计方案(2).docx》，第13～16节优先于前文近似值和旧事件说明。
参考文档 SHA256：`bf6d4c21483fe3704fc0e9ec2c56f172cc54eba376012d1a2a65b0abbcfe9dbd`。
用户已确认上一版公共 HDMI 音频底层上板正常出声；本版新增联动功能尚待队友实测。

## 本版行为

| 操作 | 声音 |
|---|---|
| 上电，四个 SW 全关 | 连续 1 kHz 测试音 |
| 进入迎新/会议/抢答，或普通场景实际切换 | 1500 Hz 提示音100 ms，然后对应六音旋律两遍，约3.1 s后回测试音 |
| 模式0，KEY3下一张，或有效KEY2上一张 | 同上，可打断并重新触发 |
| 自动轮播成功加载下一张图片 | 仅提示音100 ms，再回测试音 |
| SW4开启 | 800/1200 Hz，每500 ms换音高，持续至退出；不播放应急旋律 |
| SW4关闭，返回普通场景 | 丢弃此前旋律，重新播放提示音＋当前普通场景旋律 |
| 回菜单 | 结束事件音，直接恢复测试音，无新提示音 |
| 非图片模式调亮度/缩放/周期 | 无按键提示音，不改变原操作约定 |

迎新：C5 E5 G5 C6 G5 E5；会议：A4 C5 E5 A5 E5 C5；抢答：C5 D5 E5 G5 A5 C6。
每个音严格12000采样，提示音4800采样，报警半周期24000采样，采样率48 kHz。
音符DDS常量逐项采用新版第15节，不重新舍入或沿用旧20位教程实现。

KEY2在第一张时，原界面行为是返回自动轮播，不产生key_prev_pl，因此没有手动切图音效。
拨上未取得锁定权的普通场景SW，原scene_control不切场景，因此不播放场景切换音效。
普通场景声音跟随实际生效scene_id，不直接跟随原始拨码。

## 代码与接口

- rtl/audio_event_cdc.v：100 MHz域汇总已消抖事件，翻转请求/应答邮箱传递事件类型及绑定场景；25 MHz域两级同步并增加一拍等待，保证事件与场景编码一致。
- rtl/pcm_media_tone.v：25 MHz域小数采样节拍、32位DDS、有限BLIP/MELODY状态机及应急优先控制；媒体PCM连续输出，空闲时PCM零、gain=0。
- rtl/audio_src_mux.v：同时消费测试与媒体PCM，输出寄存器在ready=0时保持valid及左右样本；未选中的测试音继续推进，不积压。
- tools/integrated_audio.v.inc：新增顶层连接模板；prepare_projects.py生成top_audio.v及登记源码。
- rtl/audio_pcm_tone.v、HDMI协议/串化/FIFO底层、src/基线源码及原外部引脚不修改。vendor/原教程保留，新增同名媒体模块只在rtl/登记，禁止再把vendor/加入工程。

控制信号menu/emergency/scene各自两级同步；事件绑定scene另外随握手邮箱原子传递。
请求到达后等待一拍再捕获held payload，捕获后应答；源端在同步应答前绝不改变payload。
邮箱另有一个pending槽。普通机械事件间隔远大于握手往返；若未来高速事件超过槽容量，最新事件覆盖旧pending，event_overrun粘性标志置位。音效本就遵循最新事件重新触发，不无限排队。
约束只豁免同步首级；事件总线路由有40 ns datapath界限，pixel→serial仍参与真实时序检查。

## 自动事件与防重复

复用基线的img_busy/bmp_error/img_no及res_chg_pl，不新增或改变BMP模块接口。
img_busy从1到0、bmp_error=0且img_no非零形成成功加载完成脉冲；用res_chg_pl标记缩放重载，屏蔽其同序号完成事件。单图分区自动回卷完成也会叮。
这意味着缩放重读、坏图扫描/重试不会无条件触发音效。
手动切图或切场景后屏蔽自动提示音500 ms，并记录当前加载属于该操作，直到其完成。
即使TF加载超过500 ms，仍不会因同一次加载重复响。手动模式也屏蔽自动提示音。

事件在控制域识别后立刻提交；音频域在下一个采样时刻处理。
FIFO延迟通常为毫秒量级，重新触发时旧音软退出最长约5.33 ms，之后新提示音渐入。
本版能保证共享切换事件和固定音频采样时长，不能仅根据FIFO声称TF读取后整幅画面与声音一帧以内同步：实际画面加载/淡入时间依赖素材和SD卡，需要队友录像测量。

## 渐变与资源

提示音峰值16384、旋律8192、报警16384、测试音4096；默认VOLUME=256。
每个音段内部各256样本（约5.33 ms）渐入/渐出，不额外延长4800/12000/24000的正常段长度。
重复事件、菜单取消、报警抢占在短渐出后切新音，旧旋律不再恢复。
只有软过渡期间采用线性插值：test+(media-test)*gain/256；gain=0或256时分别严格等于单一音源。
这是为避免直接硬MUX在任意相位切换产生爆音的实现细节，不将两路满幅叠加；幅度有界，不削顶。
乘法采用9个像素时钟的串行移位加法，无新增DSP。每个采样间隔520/521时钟，运算时间充足。
同一audio_sine_init.vh被两路DDS复用，但保留测试音模块不修改时，TD实际推断两个独立ROM，并非一个共享物理BRAM。
若需降低总体媒体音量，可修改pcm_media_tone的VOLUME编译参数（0～256）；不占用任何新按键。

## 队友具体步骤

1. 获取dev_sim最新提交，保持main原上板工程备份。首次用JTAG/SRAM，不写Flash。
2. 插入原四分区素材TF卡，用原HDMI_B接已验证能出声的显示器，先把音量调低。
3. 直接下载audio_board/artifacts/pic_sdram_audio.bit；该文件是本版联动版。hdmi_tone.bit仍为无按键的公共底层彩条测试。
4. 如自行编译，TD关闭时执行tools/setup_gui.ps1；打开仓库根目录pic_sdram_audio.al，器件EG4S20BG256、顶层top，综合→布局布线→bitgen。检查此次Setup/Hold非负。
5. 编译/下载脚本示例（TD路径替换为本机实际安装目录）：

```powershell
# 在仓库根目录的PowerShell执行
Set-ExecutionPolicy -Scope Process Bypass
& .\audio_board\tools\build.ps1 -TdRoot "D:\Anlogic\TD_6.2.1_Engineer_6.2.168.116" -Target integrated
& .\audio_board\tools\download.ps1 -TdRoot "D:\Anlogic\TD_6.2.1_Engineer_6.2.168.116" -BitFile .\audio_board\build\integrated\pic_sdram_audio.bit
# 若使用提供的bit，BitFile改成 .\audio_board\artifacts\pic_sdram_audio.bit
```

| 验收项 | 操作与预期 |
|---|---|
| 菜单 | 四SW全关，稳定测试音；回菜单没有新叮声 |
| 三种旋律 | 分别进入SW1/2/3实际生效场景，提示音后各自旋律两遍，随后测试音 |
| 下一张/上一张 | 模式0按KEY3、非首张按KEY2，各操作只触发一次完整音效 |
| 重触发 | 旋律未结束再次切图，新提示音重新开始，未卡住或积压旧旋律 |
| 自动轮播 | 转非模式0恢复自动，等待成功加载下一张；只叮100 ms，无3 s旋律 |
| 去重 | 手动动作后记录整个读图过程；包括慢卡超过500 ms时，仍只响一次 |
| 无效/参数动作 | 无锁定权拨码不响；亮度/缩放/周期调节无手动叮声；首张KEY2不算上一张 |
| 报警覆盖 | 旋律期间拨SW4，旧旋律停止；800/1200每500 ms交替，普通切图不覆盖报警 |
| 报警恢复 | 关闭SW4，仍有普通场景时重新提示音＋当前场景旋律；无普通场景时直接测试音 |
| 长期运行 | 至少10分钟，反复上述动作，图像/OSD/按键不回退，无黑屏、爆音或断音 |

逐项保存整屏照片、带声音视频、bit SHA256、显示器型号、commit与运行时长。
实机听感、报警换音周期、自动去重和原功能均通过后再固化Flash，并断电重启复查。
本版没有执行ModelSim或其他RTL仿真；软件数学检查不等于状态机/CDC实机验收。

## 排查

- 连续测试音但按键不响：确认下载最新集成bit，确认模式0及实际key_next/key_prev动作；彩条bit不响应原按键。
- 场景音错误：以数码管生效场景号和原先触发锁定规则判断，不以最后拨上的SW判断。
- 自动换图没叮：检查是否手动模式、500 ms抑制窗口或首张场景加载；检查是否有成功的自动加载完成及BMP错误码。
- 一次切图两声：回传加载耗时、视频和所用bit哈希；不要自行把完成事件改回img_no任意变化沿。
- 报警换音特别快：报警计数必须只在48 kHz sample_tick更新，不能在25 MHz每拍更新。
- 无声/无图：先下载公共底层hdmi_tone.bit对照，按README检查显示器设置、HDMI_B及TD日志。
- 编译资源/时序异常：使用提供的工程文件，禁止重复添加vendor或旧top；保留本次完整日志，不能用旧时序记录免责。
