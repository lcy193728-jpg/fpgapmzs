# 最终架构与低功耗说明（10-21）

## 一、结论

最终版本在保持实板画面、音频、交互和素材协议不变的前提下完成收敛。正式发布采用已上板验证的 seed59 位流：

`../01_bitstream/ONLY_PROGRAM_FINAL_10_19_QOR_BEST.bit`

SHA-256：`B44A60AA348C756FBC08373CCC06E3B3B7BA08C4C226C339237E8FF31A5D49A9`

本版相对 10-18 基线将 LUT 从 17381 降至 17288（减少 93），Slice 从 9395 降至 9377（减少 18），Setup WNS 从 +0.114ns 提升至 +0.134ns；功能与专项回归仍为 12/12 通过。该结果来自完整布局布线，不以 RTL 行数或局部综合结果代替物理证据。

## 二、面向产品的体系结构

系统按“介质解析—流式处理—帧事务缓存—场景叠加—确定时序输出”组织：

```text
TF/FAT32 -> BMP 校验与尺寸识别 -> 写侧缩放/马赛克 -> SDRAM 帧缓存
                                                        |
默认配置/按键/UART -> 场景控制与帧边界提交 -> OSD/转场/显示调整 -> HDMI
片内 DDS / TF 音频 -> 事件门控与音量控制 ---------------------------> HDMI Audio
```

关键设计选择如下：

1. 图片处理放在写通路，显示读通路只承担确定节拍的取数和叠加，避免复杂算法进入 HDMI 像素关键路径。
2. 素材经 SDRAM 帧事务提交；只有完整目标帧具备资格后才在垂直边界切换，避免旧图、半帧和 OSD 抢跑。
3. 菜单、迎新、会议、抢答和应急采用分层 OSD，共享字体访问链，避免每个场景重复配置字库。
4. UART 只作为可选配置通道；CRC 正确后更新暂存配置，并在帧边界原子提交。未连接上位机时使用片内默认内容，保证上电即用。
5. 抢答输入采用同步、20ms 消抖和同周期硬件仲裁。仲裁逻辑结构边界为一个 100MHz 时钟周期（10ns），不会因软件轮询顺序产生毫秒级队列偏差。

## 三、逻辑优化与物理结果

### 3.1 已保留的有效优化

- 缩放行坐标和相关索引按真实范围收敛位宽，减少比较、加法和路由负担；完整实现后净减少 93 LUT、18 Slice，并改善 Setup WNS 0.020ns。
- OSD 字体/显示链保持共享存储和仲裁，降低重复 BRAM 消耗。
- 首帧有效、场景切换、抢答结束页显示资格统一落在帧级门控，减少各场景独立补丁式状态。
- 亮度、对比度、转场和 OSD 使用定点/移位/比较结构，避免通用处理器式逐像素运算。
- 发布流程同时约束功能回归、位流哈希、资源、Setup/Hold WNS 和原始报告，使“能仿真”不能绕过“能稳定布通”。

## 四、低功耗设计与证据

本项目采用“保持时钟树稳定、用时钟使能和数据使能降低无效翻转”的策略，不在高利用率设计中随意门控全局时钟：

- 场景未激活、静音或无事件时，DDS 相位和音频可视化历史不再无意义推进；事件到来后恢复。
- OSD、马赛克、转场等逻辑按场景和有效显示区工作，避免不可见区域传播无效像素活动。
- TF 卡、图片装载和帧提交采用请求/完成握手；空闲时不重复发起存储事务。
- 参数配置只在收到有效命令后更新，并在帧边界一次提交，减少高扇出配置网在像素期间反复变化。
- 不采用未经验证的全局时钟切断，避免新增时钟偏斜、毛刺和跨时钟风险。

`low_power_activity` 专项 VCD 中，空闲、告警休止入口及稳定休止阶段的代表性变化量均为 3，活动阶段为 96，且恢复后的功能回归通过。这证明门控行为有效，但不能由此虚构整板节电百分比；最终功耗必须用同一电压、同一显示器/TF 卡、相同采样窗口进行实测。

## 五、淘汰项与原因

以下候选已经做过完整或阶段性验证，不再重复列为后续建议：

| 候选 | 结果 | 决策 |
|---|---|---|
| 数码管与 AXIS 计数器继续缩位 | 12/12 通过，但 Slice 9519、Setup +0.049ns | 撤回 |
| 删除未使用 VGA 并行输出 | 12/12 通过，但 Slice 9579、线长显著增加 | 撤回 |
| Iris/Wipe 空闲操作数隔离 | 空闲翻转下降，但 Slice 9508、Setup -0.359ns | 撤回 |
| 抢答/判分大计数器局部门控 | 面积或时序退化 | 撤回 |
| 应急恒空分支删除、闪烁改帧计数 | 全工程映射或布线退化 | 撤回 |
| 配置 payload 继续去复位 | 物理实现无净收益 | 撤回 |

高占用 FPGA 的综合映射具有全局耦合，代码“更短”或局部翻转“更少”不保证最终面积、时序和总功耗更好；因此最终版本只保留经过全工程物理实现证明的优化。
